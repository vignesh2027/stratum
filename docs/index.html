The Problem

Your Database Is Not.

⏱

Time-series databases

🔗

Know relationships, but lack temporal ordering and semantic similarity.

Core Features

Everything You Need.
Nothing You Don't.

Temporal Index

Every record is timestamped at nanosecond precision. Time-travel queries with O(log n) range scans over an ordered BTree index. Query any past point in time.

time BETWEEN "2024-01-01" AND now()

HNSW Semantic Index

Hand-rolled Hierarchical Navigable Small World graph for O(log n) approximate nearest-neighbor search. Supports configurable recall/speed tradeoffs via M and ef parameters.

similar_to embedding([...]) WITH threshold 0.9

Causal DAG

Every record can declare its causal predecessors. Akasha maintains a directed acyclic graph of cause-and-effect relationships, queryable with BFS in both directions.

caused_by "abc123" WITH depth 5

Content-Addressed Storage

Every record is identified by the SHA-256 hash of its content. Writes are idempotent. Records are tamper-evident by construction. Backed by sled, a pure-Rust embedded DB.

id = SHA256(schema + data + timestamp)

AQSL Query Language

Akasha Query Specification Language — a composable, declarative query language with first-class temporal, semantic, and causal clauses. Parsed with a hand-written recursive descent parser.

FIND records WHERE ... AND ... LIMIT n

REST API + CLI

Full REST API built on Axum with JSON payloads. A ergonomic CLI for inserting records, running queries, and inspecting the causal graph — all from your terminal.

akasha serve --addr 0.0.0.0:7777

AQSL — Akasha Query Specification Language

Three Dimensions.
One Language.

Temporal Time-Travel Query 
FIND records
WHERE time BETWEEN "2024-01-01T00:00:00Z"
             AND "2024-03-31T23:59:59Z"
  AND schema = "payment.v2"
ORDER BY time DESC
LIMIT 100

Retrieve all payment records from Q1 2024, most recent first.

Semantic Meaning-Based Search 
FIND records
WHERE similar_to embedding([
  0.128, 0.934, -0.241, ...
])
WITH threshold 0.88
ORDER BY relevance
LIMIT 10

Find semantically similar records using cosine similarity on stored embeddings.

Causal Root-Cause Traversal 
FIND records
WHERE caused_by "a3f8e2b1..."
WITH depth 5
ORDER BY time ASC
LIMIT 50

Find everything that was triggered (directly or transitively) by a root event, up to 5 hops deep.

Combined All Three Dimensions 
FIND records
WHERE time AFTER "2024-06-01T00:00:00Z"
  AND similar_to embedding([0.91, 0.23, ...])
      WITH threshold 0.85
  AND caused_by "incident-root-id..."
      WITH depth 3
  AND tag environment = "production"
ORDER BY time DESC
LIMIT 25

The killer query — find semantically similar events, after a certain time, that were caused by a known incident, tagged as production.

curl example
# Insert a record
curl -X POST http://localhost:7777/v1/records \
  -H 'Content-Type: application/json' \
  -d '{"schema":"payment.v1",
      "data":{"amount":99.99},

# Run AQSL query
curl -X POST http://localhost:7777/v1/query \
  -d '{"aqsl":"FIND records WHERE schema = \"payment.v1\" LIMIT 10"}'
Quick Start

Up and Running in 60 Seconds

01

Install

cargo install akasha
02

Start the server

akasha serve --db ./mydata --addr 0.0.0.0:7777
03

Insert your first record

akasha insert \
  --schema "event.v1" \
  --data '{"msg":"hello akasha","level":"info"}'
04

Query it

akasha query "FIND records WHERE schema = \"event.v1\" LIMIT 10"

Or use as a Rust library

// Cargo.toml
akasha = "0.1"

// src/main.rs
use akasha::{Akasha, RecordBuilder};

let db = Akasha::open("/data/akasha").await?;

let record = RecordBuilder::new()
    .schema("payment.v1")
    .data(json!({"amount": 99.99}))
    .embedding(my_embedding_vector)
    .caused_by(vec![parent_id])
    .build()?;

let id = db.insert(record).await?;

// Query with AQSL
let results = db.query("FIND records WHERE schema = \"payment.v1\" LIMIT 50").await?;
