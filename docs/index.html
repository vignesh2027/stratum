How It Works

Three Indices. One Engine. One Query.

Stratum maintains three independent, concurrent indices over the same append-only, content-addressed record store. A query planner intersects results from each active clause at the record-ID level, then sorts and paginates.

01
⏱

Temporal Index

Every record carries a nanosecond-precision logical timestamp. Stratum maintains a concurrent BTreeMap<i64, Vec<RecordId>> that supports O(log n) range scans. You can query any past window instantly — "everything between 2pm and 3pm last Tuesday" is a single BTree range. 

time BETWEEN "2024-01-01" AND "2024-03-31"
time AFTER "2024-06-01T00:00:00Z"
time BEFORE NOW - 3600000000000  // 1h ago
02
🔍

Semantic Index (HNSW)

Records optionally carry a float32 embedding vector. Stratum indexes these in a hand-rolled Hierarchical Navigable Small World graph — the state-of-the-art algorithm for approximate nearest-neighbor search, achieving O(log n) query time. No external vector library. M=16, ef=200 by default, fully configurable. 

similar_to embedding([0.1, 0.9, ...])
  WITH threshold 0.85   // cosine similarity
03
🔗

Causal DAG

Each record can declare causal predecessors (the records that caused it). Stratum builds a bidirectional adjacency-list DAG over these declarations. You can traverse forward to find everything a record triggered, backward to find its root causes, or find the shortest causal path between any two records — all using concurrent BFS. 

caused_by "a3f8..." WITH depth 5
causes "b1c2..."   WITH depth 3
04
📦

Content-Addressed Storage

The storage layer is append-only, backed by sled (a pure-Rust embedded database). Every record's key is the SHA-256 hash of (schema + data + timestamp). This makes writes idempotent by construction — inserting the same record twice is a no-op — and every record tamper-evident. 

id = SHA256(schema ‖ timestamp ‖ data)
// identical records → identical IDs
// tamper = different ID

Core Features

Everything You Need.
Nothing You Don't.

Nanosecond Precision

Timestamps stored as i64 nanoseconds since Unix epoch. BTree range scans with configurable limits. Time-travel to any past moment in O(log n).

Hand-Rolled HNSW

Zero external dependencies for vector search. Implements the Malkov & Yashunin 2018 algorithm from scratch. M=16, ef_construction=200, tunable recall/speed.

Causal Graph Traversal

Declare predecessors at write time. Bidirectional adjacency lists for forward (effects) and backward (causes) BFS. Shortest path between any two records.

SQSL Query Language

Stratum Query Specification Language — composable temporal, semantic, and causal clauses in one expression. Parsed by a hand-written recursive descent parser.

Embeddable Library

Use Stratum as a library in any Rust project. Zero configuration, no external services. Open a database with one function call. Async-native with Tokio.

REST API + CLI

Full REST API built with Axum. 9 endpoints covering all three dimensions. CORS-enabled. Plus a complete CLI for interactive use and shell scripting.

Tamper-Evident by Design

Content-addressed with SHA-256. Idempotent writes — the same record always produces the same ID. Detect data corruption or tampering trivially.

Schema + Metadata Tags

Records carry a versioned schema name (e.g. "payment.v2") and arbitrary key-value metadata tags. Filter by either in SQSL. Schema evolution is append-only.

Startup Index Rebuild

On open, Stratum scans all stored records and rebuilds all three in-memory indices atomically. Restarts are safe and fast — no WAL replay needed.

Use Cases

Built for Real Engineering Problems

Stratum was designed for scenarios where the temporal, semantic, and causal dimensions of data intersect — situations where existing databases force you to build expensive multi-system pipelines.

🔎

Incident Investigation & SRE

A payment service is failing in production. With three separate databases, you'd query InfluxDB for the timeline, a vector DB for similar past incidents, and a graph DB for the dependency chain — and manually stitch the results together.

With Stratum, you issue one query: "Give me all production events from the last hour, semantically similar to this error signature, that were triggered by the recent deploy." The causal chain and similar past incidents appear together, ordered by time. 

FIND records
WHERE time AFTER "2024-03-15T18:00:00Z"
  AND similar_to embedding([0.88, -0.23, ...]) WITH threshold 0.82
  AND caused_by "deploy-b7f3c1..." WITH depth 10
  AND tag environment = "production"
ORDER BY time ASC LIMIT 200
🤖

AI Memory & Agentic Systems

AI agents and LLM applications need persistent memory — a store of past observations, tool calls, reasoning steps, and responses — that can be retrieved by semantic similarity (what is this message about?) and temporal context (when did this happen?) and causal relationships (what did this observation cause the agent to do?).

Stratum is purpose-built for this. Store every agent action as a record with an embedding and causal link to its triggering observation. Retrieve relevant context for any new input using all three dimensions simultaneously. 

FIND records
WHERE similar_to embedding(current_context_embedding)
    WITH threshold 0.9
  AND time AFTER session_start_time
  AND schema = "agent.observation.v1"
ORDER BY relevance LIMIT 20
📋

Event Sourcing & Audit Logs

Event sourcing systems need an immutable event log with replay capability, but they also need to answer questions like "what commands caused this aggregate state?" and "which events from last quarter are semantically related to this compliance issue?"

Stratum's append-only, content-addressed log is a natural event store. The causal graph models command-event chains. Semantic embeddings on event payloads make compliance investigations instant. 

// Replay state up to a point in time
FIND records
WHERE time BEFORE "2024-09-01T00:00:00Z"
  AND schema = "account.event.v2"
ORDER BY time ASC
🏥

Healthcare & Clinical Decisions

Clinical decision trails need time (when was this prescribed?), semantics (find similar cases from the literature), and causality (what led to this outcome?). Stratum provides GDPR-compliant storage with the right-to-erasure delete API, tamper-evident records for regulatory audits, and causal chains for explainability. 

// Find similar patient cases and their causal chains
FIND records
WHERE similar_to embedding(symptoms_vector) WITH threshold 0.87
  AND schema = "clinical.observation.v1"
ORDER BY relevance LIMIT 10
📈

Financial Systems & Trading

Financial systems need to track transaction causality (a refund was caused by a charge, which was caused by a cart checkout), correlate with temporal market data, and find semantically similar past transactions for fraud detection — all with nanosecond timestamp precision and immutable records for regulatory compliance. 

// Find causally related transactions with similar patterns
FIND records
WHERE caused_by "order-8f2a..." WITH depth 5
  AND similar_to embedding(fraud_pattern) WITH threshold 0.80
  AND time BETWEEN "2024-01-01" AND "2024-12-31"
🔬

Scientific Research & Reproducibility

Research workflows have natural causal structure: hypothesis → experiment → result → publication. Stratum lets you model these dependencies explicitly. Find all results causally derived from a hypothesis, search for semantically related prior work, and replay the full provenance chain of any finding. 

// Full provenance chain for a finding
FIND records
WHERE causes "finding-c9d2..." WITH depth 20
  AND schema = "experiment.v1"
ORDER BY time ASC

SQSL — Stratum Query Specification Language

A Query Language Built
for Three Dimensions

SQSL is parsed by a hand-written recursive descent parser — zero external parsing dependencies. Clauses can be combined with AND in any order. The query planner intersects result sets from each clause, then applies ordering and pagination.

Grammar (simplified)
query    := FIND records [WHERE clause (AND clause)*]
             [ORDER BY (time ASC | time DESC | relevance)]
             [LIMIT n] [OFFSET n]

clause   := time BETWEEN time_ref AND time_ref
           | time AFTER time_ref
           | time BEFORE time_ref
           | similar_to embedding([f32, ...]) [WITH threshold f32]
           | caused_by hex_id [WITH depth n]
           | causes hex_id [WITH depth n]
           | schema = "name"
           | tag key = "value"

time_ref := "ISO-8601" | unix_nanos | NOW | NOW - nanos
Temporal

Time-range with time-travel

FIND records
WHERE time BETWEEN "2024-Q1-start" AND "2024-Q1-end"
  AND schema = "payment.v2"
ORDER BY time DESC LIMIT 100

O(log n) range scan over the temporal BTree index.

Semantic

Nearest-neighbor semantic search

FIND records
WHERE similar_to embedding([0.91, 0.23, -0.14, ...])
    WITH threshold 0.88
ORDER BY relevance LIMIT 10

O(log n) HNSW approximate nearest-neighbor. Cosine similarity threshold filters results.

Causal

Root-cause traversal

FIND records
WHERE caused_by "root-event-a3f8..."
    WITH depth 8
ORDER BY time ASC LIMIT 500

BFS over the causal DAG. Depth controls how many hops to traverse.

All Three Dimensions

The query that doesn't exist in any other database

FIND records
WHERE time BETWEEN "2024-01-01T00:00:00Z" AND "2024-12-31T23:59:59Z"
  AND similar_to embedding([0.91, 0.23, -0.14, 0.05, ...]) WITH threshold 0.82
  AND caused_by "incident-root-id-a3f8e2b1..." WITH depth 5
  AND tag environment = "production"
  AND schema = "alert.v2"
ORDER BY time DESC LIMIT 25

All five clause types combined. The query planner intersects all result sets, applies sort, then paginates. Each index is queried independently and concurrently.

Up and Running in 60 Seconds

01 · Install
# From crates.io (coming soon)
cargo install stratum

# From source
git clone https://github.com/vignesh2027/stratum
cd stratum
cargo build --release
02 · Start the Server
stratum serve --db ./mydata --addr 0.0.0.0:7777

03 · Insert Records
# Via CLI
ID=$(stratum insert \
  --schema "payment.v2" \
  --data '{"amount": 99.99, "currency": "USD"}')

# Via REST API
curl -X POST http://localhost:7777/v1/records \
  -H 'Content-Type: application/json' \
  -d '{
    "schema": "payment.v2",
    "data": {"amount": 99.99},
    "embedding": [0.91, 0.23, -0.14],
    "metadata": {"environment": "production"}
  }'
# → {"id": "a3f8e2b1c4d9f6e2..."}
04 · Query with SQSL
# Via CLI
stratum query "FIND records WHERE schema = \"payment.v2\" LIMIT 10"

# Via REST API
curl -X POST http://localhost:7777/v1/query \
  -H 'Content-Type: application/json' \
  -d '{"sqsl": "FIND records WHERE time AFTER \"2024-01-01T00:00:00Z\" AND schema = \"payment.v2\" ORDER BY time DESC LIMIT 100"}'
05 · Use as a Rust Library
// Cargo.toml
[dependencies]
stratum = "0.1"
tokio  = { version = "1", features = ["full"] }

// src/main.rs
use stratum::{Stratum, RecordBuilder};

let db = Stratum::open("/data/stratum").await?;

let record = RecordBuilder::new()
    .schema("event.v1")
    .data(json!({"type": "user_signup", "user_id": "u42"}))
    .embedding(embed("user signup"))
    .tag("environment", "production")
    .build()?;

let id = db.insert(record).await?;

// Query via SQSL
let results = db.query(
    "FIND records WHERE schema = \"event.v1\" LIMIT 50"
).await?;

// Or use the typed API
let similar = db.find_similar(&embedding, 10, 0.85).await?;
let effects = db.find_effects(&id, 5).await?;

Insert a record with embedding and causal link

curl -X POST http://localhost:7777/v1/records \
